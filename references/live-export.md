# 动画、原Live与Apple输出

本文件仅用于用户明确要求动态或Apple实况资源的情况。默认静态图片无需阅读运动计划、运行FFmpeg、探测原Live视频或完成Apple封装。用户已有插画时，缺少视频或旧运动计划无效不影响静态调整。

## 输入规则

| 输入 | 上半区域 | 下半区域 |
| --- | --- | --- |
| 普通照片／扫描后的裁剪照片 | 原片本机静态显示，逐渲染帧固定 | 局部插画循环 |
| JPG或HEIC＋确认配对的MOV | 原视频，保留动作、速度、时长与可用音轨 | 共用时间轴的局部动画 |
| 只有Live静帧 | 提示缺少配套视频，按静态处理 | 局部插画循环 |

优先按内容标识配对。同名只提供预览确认；标识冲突不能被同名覆盖。单独MOV不能冒充原始Live。CLI接受 `--live-video` 的前提是配对已在导入流程确认，CLI本身不做自动配对。

纸质扫描不能恢复原Live动作。不要将修复静帧的效果自动套到原视频，也不要补帧、倒放或用另一视频替换原动作。

## 依赖与工具边界

- 静态排版：Python、Pillow、NumPy、OpenCV，无需云端连接。
- 视频：FFmpeg；`imageio-ffmpeg` 可提供静态路线编码器。原Live另需ffprobe读取时长、轨道与HDR标记。
- Apple资源：独立 [Live Photo Box CLI](https://github.com/LengxiQwQ/live-photo-box/blob/master/docs/CLI-User-Guide.zh-CN.md)、ffprobe、ExifTool。它们不生成插画。
- 云端生成：用户指定且可用的生图工具。Luna做视觉决策与工具编排，本机渲染器负责运动；不能将其描述为图生视频模型。

工具放在PATH，或设置绝对路径环境变量 `PHOTO_ECHO_FFMPEG`、`PHOTO_ECHO_FFPROBE`、`PHOTO_ECHO_EXIFTOOL`、`PHOTO_ECHO_LIVEPHOTOBOX`。旧LIVE_HANDBOOK前缀仍兼容。工具不随仓库打包，按原项目安装。

skill使用宿主实际提供的工具，不要求Windows桌面工作台或EXE。已有源图、插画与参数就可在本机处理；新生图的服务和模型根据用户选择与宿主能力确定，不修改全局模型配置。

## 本机渲染

只在插画资产的小区域做形变，纸面纹理固定随机种子，保护笔迹优先。坐标相对于去底裁净后的插画；去底或重新生图后重新确认计划。

新版先羽化位移场，再对插画单次重采样；不混合原线条和移位线条造成双影。水纹采用连续推进的相位，叶端根部固定、位置响应略有差别；边缘位移平滑归零。单个波形的正弦振幅最多6个成图插画像素，并限制位移梯度，不能靠大幅拉扯提高动感。渲染器版本记录为continuous-local-motion-1。

选择动态输出后，普通照片默认3秒、30fps、H.264、SDR。原Live按旋转信息转正并等比完整适配照片区域，不为铺满窗口而裁切。保留声音时重新编码为AAC，不能声称音轨压缩比特完全相同。HDR经显式SDR转换后记录提示，不承诺等同原HDR显示。

封面从最终视频指定帧取出。所有输入共享一个成品目录，按源文件名输出；重名加序号防覆盖。插画、参考与记录在.photo-echo内部工作区，视频临时编码成功后才发布成品。

空计划可以生成静止下半预览，但须报告未配置运动；文件后缀MP4不等于插画已经动起来。

## Apple实况不是一个普通HEIF文件

HEIC／HEIF可以承载照片，但Apple Live Photo通常是匹配的静态资源与视频资源。本仓库选择 **JPG＋MOV** 输出；不把GIF、MP4、ZIP或任意HEIF当作完整Apple实况。

路线：封面JPG＋合成MP4 → 中间Motion Photo → 拆分Apple JPG＋MOV。示意命令：

```sh
lpb merge cover.jpg preview.mp4 -p motionphoto -o motion --key-timestamp 1.5 -j 1 -y
lpb split motion-photo.jpg -p apple -f jpg+mov -o apple --key-timestamp 1.5 -j 1 -y
```

实际中间文件名由工具输出确定。`package_apple` 发现输出，不假定固定名称。在短、独立临时路径封装，降低Windows深层中文路径与原生MAX_PATH问题；只复制验证通过的配对资源。

电脑校验必须包括：

1. 静态与MOV有相同内容标识。
2. MOV有定时元数据轨道及 `still-image-time` 信息。
3. 封面时间对应实际定时轨道位置，不只检查字串存在。
4. 视频尺寸、方向、时长和封面构图符合交付。

封装后不能普通转码配对MOV，可能丢元数据。失败保留MP4与封面，报告 `apple_incomplete`、`apple_verified=false`，CLI返回2；不能显示全部成功。

`apple_verified=true`仅代表电脑检查。`phone_verified=true`需要真实iPhone导入、显示LIVE并长按播放。电脑使用者直接播放MP4，无需手机配合。

## 批量、缓存和恢复

对每个输入用稳定ID或内容哈希创建目录，保存选择、来源摘要、提示词版本、原稿、处理后资产、计划与阶段。运行时任务编号不是永久素材ID。

明确要求改画法或替换插画时才重新生图；来源和提示词变化先检查现有插画是否仍可用，不因版本号变化自动消耗生图额度。改比例、插画区高度、大小、英文配文、强度或封面时复用插画。静态调整不重新分析运动。

图片取得后先落盘再去底、分析运动。后续失败重试复用该图。重新生图失败保存待替换意图，不能因旧图仍在就把重试当旧作品缓存命中。恢复只将进行中状态改为中断，不自动云端调用。

CLI的batch模式读取Agent内部任务清单，一次调用顺序处理整个输入组，统一输出。没有桌面任务按钮；取消保留已完成文件，并记录未处理数量。只重试指定失败项，不复制其他照片的取景、焦点或蒙版。

`recompose --from-output` 从 `.photo-echo/` 读取每张最近成功的参数与素材快照。可只选择部分原文件名或稳定素材ID；默认输出静态图片，保留各张未指定更改的配文、纸面和插画大小。仍在结果目录追加新版本，旧成品不覆盖；加 `--zip` 只打包本次选中的结果，不包含源图和内部缓存。
